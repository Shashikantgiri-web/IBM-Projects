# 16 — Deployment Guide
## Employee Performance Intelligence System (EPIS)

---

## 1. Overview

EPIS is deployed using:
- **Vercel** — for the Next.js frontend and API routes (serverless)
- **Supabase** — for the PostgreSQL database and authentication (already live)

This guide covers three environments:

| Environment | URL | Purpose |
|---|---|---|
| Local Development | http://localhost:3000 | Day-to-day coding and testing |
| Preview (Staging) | Auto-generated by Vercel per PR | Testing before merging |
| Production | https://epis.vercel.app | Live application |

---

## 3. Local Development Setup

### Step 1 — Clone the Repository
```bash
git clone https://github.com/your-org/epis.git
cd epis
```

### Step 2 — Install Dependencies
```bash
npm install
```

### Step 3 — Set Up Environment Variables

Create a `.env.local` file in the root of the project:

```bash
touch .env.local
```

Add the following variables (get values from your team's Supabase project):

```env
# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key-here

# App
NEXT_PUBLIC_APP_URL=http://localhost:3000
NEXT_PUBLIC_APP_NAME=EPIS
```

> ⚠️ CRITICAL: Never commit `.env.local` to Git. It is already listed in `.gitignore`.

### Step 4 — Start Development Server
```bash
npm run dev
```

Open http://localhost:3000 in your browser. The app should load the login page.

### Step 5 — Verify Supabase Connection

On the login page, try logging in with a test account. If the login works and redirects to a dashboard, the Supabase connection is working correctly.

## 4. Supabase Configuration

The database is already set up by the Data Engineering team. However, you need to configure the following in the Supabase dashboard for the web app to work:

### 4.1 Enable Row Level Security (RLS)

In the Supabase dashboard → Table Editor → for each table → enable RLS.

Then add the following policies (adjust to match your exact schema):

**employees table — CEO sees all, Manager sees own dept, Employee sees own row:**
```sql
-- Allow CEO and Tester to see all employees
CREATE POLICY "ceo_see_all_employees" ON employees
FOR SELECT USING (
  EXISTS (
    SELECT 1 FROM users
    WHERE users.id = auth.uid()
    AND users.role IN ('ceo', 'tester')
  )
);

-- Allow Manager to see only their department
CREATE POLICY "manager_see_dept_employees" ON employees
FOR SELECT USING (
  EXISTS (
    SELECT 1 FROM users
    WHERE users.id = auth.uid()
    AND users.role = 'manager'
    AND users.department_id = employees.department_id
  )
);

-- Allow Employee to see only their own record
CREATE POLICY "employee_own_record" ON employees
FOR SELECT USING (
  EXISTS (
    SELECT 1 FROM users
    WHERE users.id = auth.uid()
    AND users.employee_id = employees.id
  )
);
```

Apply similar policies to: `salary`, `performance`, `training`, `satisfaction`, `attendance`, `experience`, `promotion`.

### 4.2 Configure Auth Email Templates

In Supabase dashboard → Authentication → Email Templates:

- **Confirm signup** — customize with EPIS branding
- **Reset password** — customize subject to "EPIS — Password Reset Request"
- Set the redirect URL to: `https://epis.vercel.app/login`

### 4.3 Configure Auth Redirect URLs

In Supabase dashboard → Authentication → URL Configuration:

- **Site URL:** `https://epis.vercel.app`
- **Redirect URLs (allowed list):**
  ```
  http://localhost:3000/**
  https://epis.vercel.app/**
  https://*.vercel.app/**
  ```

### 4.4 Create Application Users

Until Version 2 adds an admin panel, users are created manually:

1. Go to Supabase dashboard → Authentication → Users → Add User
2. Enter email and set a temporary password
3. Go to the `users` table → Insert row:
   ```sql
   INSERT INTO users (id, email, role, department_id, display_name)
   VALUES (
     'auth-user-uuid-from-step-1',
     'ceo@company.com',
     'ceo',
     NULL,
     'Company CEO'
   );
   ```
4. Inform the user of their temporary password and ask them to change it on first login

## 6. Deploying to Vercel

### First-Time Setup

**Step 1 — Connect GitHub to Vercel**
1. Go to https://vercel.com → Log in
2. Click "Add New Project"
3. Import your GitHub repository
4. Vercel will auto-detect that it is a Next.js project

**Step 2 — Configure Environment Variables**

In Vercel project settings → Environment Variables → add:

```
NEXT_PUBLIC_SUPABASE_URL        → Production, Preview, Development
NEXT_PUBLIC_SUPABASE_ANON_KEY   → Production, Preview, Development
SUPABASE_SERVICE_ROLE_KEY       → Production, Preview, Development
NEXT_PUBLIC_APP_URL             → Production: https://epis.vercel.app
```

**Step 3 — Deploy**
Click "Deploy". Vercel will run `npm run build` and deploy automatically.

The app will be live at: `https://epis.vercel.app` (or your chosen domain).

---

### Subsequent Deployments

Every `git push` to the `main` branch triggers an automatic production deployment on Vercel.

Every pull request automatically gets a **preview deployment** at a unique URL — useful for reviewing features before merging.

```
git push origin main          → Auto-deploys to production
git push origin feature/xyz   → Creates a Vercel preview URL
```

## 7. Environment Variable Reference

| Variable | Required | Where Used | Notes |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | Client + Server | Safe to expose — public key |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | Client + Server | Safe to expose — public key |

| `NEXT_PUBLIC_APP_URL` | ✅ | Client | Base URL for redirects |
| `NEXT_PUBLIC_APP_NAME` | Optional | Client | "EPIS" — for display only |

- [ ] `npm run test` — all tests pass

- [ ] All charts load correctly
- [ ] Export CSV works
- [ ] Dark mode works

- [ ] No console errors in production build

- [ ] Lighthouse performance score ≥ 85

## 9. Rollback Procedure

If a production deployment breaks the app:

1. Go to Vercel dashboard → your project → Deployments
2. Find the last working deployment
3. Click the three-dot menu → "Promote to Production"
4. The previous version is restored within seconds

## 10. Common Issues & Fixes

| Issue | Cause | Fix |
|---|---|---|
| "Invalid API key" on login | Wrong Supabase keys in .env.local | Double-check NEXT_PUBLIC_SUPABASE_ANON_KEY |
| Redirect loop on login | Auth state not resolving | Check AuthProvider is wrapping the app in layout.tsx |
| Charts show no data | API returning empty | Check RLS policies are configured correctly |
| 401 on all API calls | Service role key missing | Add SUPABASE_SERVICE_ROLE_KEY to Vercel env vars |
| Build fails on Vercel | TypeScript errors | Run `npm run type-check` locally first |
| Supabase auth redirect fails | Wrong redirect URL | Add your Vercel URL to Supabase allowed redirect URLs |
| White screen after login | Role not set in users table | Insert user row with correct role in Supabase users table |
